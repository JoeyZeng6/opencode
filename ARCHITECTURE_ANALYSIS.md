# OpenCode 项目架构分析文档

## 一、项目概述

**OpenCode** 是一个开源的 AI 驱动开发工具和编程代理，类似于 Claude Code，但 100% 开源且提供商无关。

- **仓库**: https://github.com/anomalyco/opencode
- **版本**: 1.1.21
- **许可证**: MIT
- **主要语言**: TypeScript
- **运行时**: Bun 1.3.6

**职责**:

**工具注册流程**:

```
2. 加载 NPM 插件工具
3. 按权限过滤可用工具
4. 初始化工具参数和描述
5. 暴露给 LLM 调用
```

#### 4.2.4 权限系统 (Permission)

**核心文件**: `packages/opencode/src/permission/next.ts`

**职责**:
- 细粒度权限控制
- 基于模式的规则匹配
- 用户交互式权限审批
- 权限持久化

**权限动作**:
- `allow` - 允许操作
- `deny` - 拒绝操作 (自动)
- `ask` - 询问用户

**权限评估流程**:
```typescript
// 1. 遍历所有模式
for (const pattern of request.patterns) {
  // 2. 评估规则
  const rule = evaluate(request.permission, pattern, ruleset, approved)

  // 3. 根据动作处理
  if (rule.action === "deny")
    throw new DeniedError(ruleset)

  if (rule.action === "ask") {
    // 发送事件到客户端，等待用户响应
    return new Promise((resolve, reject) => {
      Bus.publish(Event.Asked, info)
      // 等待 PermissionNext.reply()
    })
  }

  if (rule.action === "allow") continue
}
```

**权限规则示例**:
```typescript
{
  "*": "allow",                    // 默认允许所有
  "edit": { "*.env": "ask" },      // 编辑 .env 文件需要询问
  "bash": "ask",                   // bash 命令需要询问
  "question": "deny",              // 禁止使用 question 工具
}
```

## 五、交互流程分析

### 5.1 用户请求处理流程

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. 用户输入                                                      │
│    "帮我添加一个登录功能"                                        │
└────────────────┬────────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ 2. CLI/Web/Desktop 客户端                                        │
│    - 接收用户输入                                                │
│    - 创建/获取会话                                               │
│    - 发送 HTTP 请求到服务器                                      │
└────────────────┬────────────────────────────────────────────────┘
                 │ POST /api/session/{sessionID}/message
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ 3. Server (Hono)                                                │
│    - 验证请求                                                    │
│    - 调用 SessionProcessor.process()                            │
└────────────────┬────────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ 4. SessionProcessor (processor.ts)                              │
│    - 构建消息上下文                                              │
│    - 调用 LLM.stream()                                          │
└────────────────┬────────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ 5. LLM 流式响应循环                                              │
│                                                                  │
│  ┌────────────────────────────────────────────────────────┐    │
│  │ while (true) {                                          │    │
│  │   for await (const value of stream.fullStream) {       │    │
│  │     switch (value.type) {                              │    │
│  │       case "text-delta":                               │    │
│  │         // 流式输出文本                                  │    │
│  │         break;                                          │    │
│  │                                                          │    │
│  │       case "tool-call":                                 │    │
│  │         // 执行工具调用                                  │    │
│  │         await executeTool(value);                       │    │
│  │         break;                                          │    │
│  │                                                          │    │
│  │       case "tool-result":                               │    │
│  │         // 工具返回结果                                  │    │
│  │         await handleToolResult(value);                  │    │
│  │         break;                                          │    │
│  │                                                          │    │
│  │       case "finish-step":                               │    │
│  │         // 步骤完成，生成 diff                            │    │
│  │         await generatePatch();                          │    │
│  │         break;                                          │    │
│  │     }                                                   │    │
│  │   }                                                     │    │
│  │   if (finish || blocked || error) break;                │    │
│  │ }                                                       │    │
│  └────────────────────────────────────────────────────────┘    │
└────────────────┬────────────────────────────────────────────────┘
                 │ SSE (Server-Sent Events)
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ 6. 客户端接收更新                                                │
│    - 实时显示文本输出                                            │
│    - 显示工具执行状态                                            │
│    - 显示代码差异                                                │
└─────────────────────────────────────────────────────────────────┘
```

## 六、关键设计决策

### 6.1 提供商无关设计
- **问题**: 避免被单一 AI 提供商锁定
- **解决方案**: 抽象 Provider 接口，支持 15+ 提供商
- **实现**: `packages/opencode/src/provider/provider.ts`

### 6.2 基于工具的交互
- **问题**: LLM 需要结构化方式与系统交互
- **解决方案**: Function Calling + 工具注册系统
- **优势**:
  - 类型安全
  - 权限可控
  - 易于扩展

### 6.3 多代理架构
- **问题**: 不同任务需要不同能力和权限
- **解决方案**: 定义多种代理，每个有专门的权限和提示
- **优势**:
  - 分离关注点
  - 精确权限控制
  - 并行任务执行

### 6.4 事件驱动架构
- **问题**: 多客户端需要实时同步状态
- **解决方案**: 类型安全的事件总线 + SSE 流式传输
- **优势**:
  - 实时更新
  - 解耦组件
  - 易于扩展

### 6.5 权限系统
- **问题**: AI 需要受限访问以防止误操作
- **解决方案**: 基于模式的规则引擎 + 用户交互式审批
- **特性**:
  - 细粒度控制
  - 通配符匹配
  - 会话级规则
  - 持久化批准

## 八、配置系统

### 8.1 配置层次

```
1. 全局配置 (~/.opencode/config.json)
   └── 用户默认设置

2. 项目配置 (.opencode/config.json)
   └── 项目特定设置

3. 远程配置 (well-known URL)
   └── 组织级配置

4. 命令行标志
   └── 临时覆盖
```

### 8.2 配置选项

```typescript
{
  // AI 提供商
  provider: {
    default: "anthropic",
    anthropic: { apiKey: "..." },
    openai: { apiKey: "..." },
  },

  // 默认代理
  default_agent: "build",

  // 自定义代理
  agent: {
    my_agent: {
      model: "anthropic/claude-sonnet-4",
      temperature: 0.7,
      permission: { bash: "allow" }
    }
  },

  // 权限规则
  permission: {
    "*": "allow",
    bash: "ask",
    edit: { "*.env": "ask" }
  },

  // 分享设置
  share: "auto",  // auto | disabled | manual

  // 实验性功能
  experimental: {
    openTelemetry: true,
    continue_loop_on_deny: false,
    batch_tool: true,
  }
}
```

## 十一、总结

OpenCode 是一个设计精良的 AI 驱动开发工具，其核心优势包括:

1. **架构清晰**: 模块职责明确，易于理解和扩展
2. **提供商无关**: 支持多家 AI 提供商，避免供应商锁定
3. **权限安全**: 细粒度权限控制，用户对 AI 操作有完全掌控
4. **多客户端支持**: CLI、Web、Desktop 统一体验
5. **事件驱动**: 实时状态同步，响应迅速
6. **易于扩展**: 支持自定义工具、代理和 MCP 集成

该项目采用现代技术栈 (Bun + TypeScript + Hono + SolidJS)，性能优异，开发体验良好。
